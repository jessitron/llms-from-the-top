Calling the API

Every request needs an x-api-key header — ask Jess for the value.

/v1/completions

Raw text completion. Given a prompt, the model continues it. No chat structure, no instruction-following unless the model happens to have been trained for it.

URI: https://llms-from-the-top.jessitron.com/v1/completions

Method: POST

Headers:

  • content-type: application/json — required
  • x-api-key: <your key> — required
  • x-conversation-id: <a unique ID for this agent run, like a UUID> — optional
  • x-agent-name: <your agent's name> — optional

Input format (JSON body):

{ "model": "base", "prompt": "Once upon a time, a giant" }
  • model — "base" or "chat". Defaults to "chat" if omitted.
  • prompt — the text to continue.
  • max_tokens — optional, defaults to 100.

Output format (JSON body, vLLM's OpenAI-compatible completions response):

{
  "choices": [{ "text": " ...continuation...", "finish_reason": "stop" }]
}
  • choices[0].text — the completion.
  • choices[0].finish_reason — why it stopped, e.g. "stop" or "length".
curl https://llms-from-the-top.jessitron.com/v1/completions \
  -H "x-api-key: <your key>" -H "content-type: application/json" \
  -d '{"model": "base", "prompt": "Once upon a time, a giant"}'

/v1/chat/completions

The chat API. Looks like OpenAI's chat completions API (my endpoint doesn't support all of it, and support varies by model).

URI: https://llms-from-the-top.jessitron.com/v1/chat/completions

Method: POST

Same headers as above (content-type and x-api-key required; x-conversation-id and x-agent-name optional). 

curl https://llms-from-the-top.jessitron.com/v1/chat/completions \
  -H "x-api-key: <your key>" -H "content-type: application/json" \
  -d '{"messages": [{"role": "user", "content": "hi"}]}'

Valid model values: base, chat, better, haiku, luna, nano (omit for the default chat model).

The request/response shape grows as the workshop progresses — messages, system prompts, tool definitions and tool calls. See these, in order, for the details:

  • examples/2-chat/README.md — messages format, request/response shape
  • examples/3-system-prompt/README.md — adding a system message
  • examples/4-tools/README.md — tool definitions, tool calls, tool results

Available models

Alias Real model Size Inference server
base mistralai/Mistral-7B-v0.1 7B Modal (vLLM)
chat mistralai/Mistral-7B-Instruct-v0.1 7B Modal (vLLM)
better mistralai/Mistral-Small-3.2-24B-Instruct-2506 24B Modal (vLLM)
haiku claude-haiku-4-5 undisclosed Anthropic API
luna gpt-4o-mini undisclosed OpenAI API
nano gpt-4.1-nano undisclosed OpenAI API

base isn't instruction-tuned, so it only makes sense on /v1/completions. Everything else — including chat — works on /v1/chat/completions; haiku, luna, and nano support that endpoint only.
